# Описание программного проекта

## 1. Назначение системы

Система оформления и контроля пропусков предназначена для автоматизации процессов подачи, обработки и контроля заявок на оформление пропусков в организации.

Основная задача системы заключается в обеспечении централизованной работы с заявками на получение пропусков, контроле состояния заявок и оформленных пропусков, а также в разграничении доступа пользователей к информации в соответствии с их ролями.

Версия проекта v0.2 предназначена для фиксации требований безопасности, защищаемых активов, правил разграничения доступа и приёмочных сценариев. Полная реализация всех механизмов безопасности планируется на последующих этапах разработки.

## 2. Границы системы

### 2.1. В границы системы входят

В состав рассматриваемой программной системы входят:

- пользовательский интерфейс;
- серверное приложение на Python;
- модуль конфигурации;
- модуль аутентификации;
- модуль управления доступом;
- модуль обработки заявок;
- модуль управления пропусками;
- подсистема журналирования событий безопасности;
- подсистема формирования отчётов;
- база данных;
- автоматические тесты;
- проектная документация;
- конфигурационные файлы приложения.

### 2.2. Внешние по отношению к системе компоненты

Внешними по отношению к приложению рассматриваются:

- система физического контроля доступа организации;
- турникеты и другие устройства проверки пропусков;
- внешние источники сведений о сотрудниках и посетителях;
- операционная система и аппаратная среда, на которой запускается приложение;
- внешняя сеть, используемая для взаимодействия с приложением.

В учебной версии проекта реальные интеграции с физическими средствами контроля доступа и внешними информационными системами не реализуются. Для проведения проверок используются искусственные тестовые данные.

## 3. Пользователи системы

В системе предусмотрены три основные роли пользователей:

### 3.1. Заявитель

Заявитель использует систему для:

- подачи заявки на оформление пропуска;
- просмотра собственных заявок;
- отслеживания состояния собственных заявок;
- просмотра информации, связанной с собственными пропусками.

Заявитель не должен иметь доступа к заявкам других пользователей, административным функциям и журналу событий безопасности.

### 3.2. Сотрудник службы безопасности

Сотрудник службы безопасности использует систему для:

- просмотра поступивших заявок;
- проверки предоставленных сведений;
- принятия решения по заявке;
- изменения состояния оформленных пропусков;
- поиска и фильтрации заявок;
- формирования предусмотренных системой отчётов.

Сотрудник службы безопасности не должен иметь административных полномочий по управлению ролями пользователей и настройками системы.

### 3.3. Администратор

Администратор выполняет административные функции:

- управление учётными записями пользователей;
- назначение и изменение ролей;
- контроль состояния учётных записей;
- просмотр журнала событий безопасности;
- управление административными настройками;
- контроль конфигурации системы.

Администратор не получает автоматически права на изменение прикладных данных заявок и пропусков, если такое право не предусмотрено отдельным полномочием.

## 4. Основные функции

Основные функции системы:

- регистрация и аутентификация пользователей;
- создание заявок на оформление пропусков;
- просмотр собственных заявок заявителем;
- просмотр и проверка заявок сотрудником службы безопасности;
- одобрение или отклонение заявок;
- изменение состояния оформленных пропусков;
- поиск и фильтрация данных;
- разграничение доступа на основе ролей;
- управление учётными записями пользователей;
- управление ролями пользователей;
- журналирование событий безопасности;
- формирование отчётов;
- выполнение проверок корректности вводимых данных.

## 5. Обрабатываемые данные

Система может обрабатывать следующие категории данных:

- идентификационные данные пользователей;
- учётные данные;
- сведения о заявках на оформление пропусков;
- сведения об оформленных пропусках;
- статусы заявок и пропусков;
- решения по заявкам;
- историю изменений;
- записи журнала событий безопасности;
- параметры конфигурации;
- данные формируемых отчётов.

Реальные пароли, секретные ключи и иные конфиденциальные значения не включаются в проектную документацию и исходный код.

## 6. Защищаемые активы

К основным защищаемым активам относятся:

- заявки на оформление пропусков;
- сведения об оформленных пропусках;
- учётные записи и роли пользователей;
- журнал событий безопасности;
- параметры конфигурации и секретные параметры;
- исходный код приложения;
- история изменений заявок и пропусков;
- работоспособность сервиса оформления пропусков.

Подробный реестр защищаемых активов и оценка их значимости приведены в файле `assets.md`.

## 8. Ограничения безопасности

При работе системы должны соблюдаться следующие ограничения:

- доступ к функциям системы предоставляется в соответствии с ролью пользователя;
- действия, не разрешённые матрицей доступа, считаются запрещёнными;
- заявитель имеет доступ только к собственным заявкам;
- изменение состояния заявок и пропусков выполняется только уполномоченными сотрудниками;
- управление учётными записями и ролями доступно только администратору;
- журнал событий безопасности доступен только уполномоченным пользователям;
- секретные параметры не должны включаться в исходный код;
- файл `.env` не должен включаться в отслеживаемое содержимое Git;
- запрещённые операции не должны приводить к изменению защищаемых данных;
- для критичных механизмов безопасности должны использоваться позитивные и негативные тесты.

## 9. Версия проекта

Документация данного этапа относится к версии `v0.2`.

В версии `v0.2` зафиксированы:

- назначение и границы системы;
- роли пользователей;
