# Матрица доступа

## 1. Роли пользователей

В системе определены три основные роли пользователей:

- **Заявитель** — создаёт заявку на оформление пропуска, просматривает собственные заявки и отслеживает их состояние.
- **Сотрудник службы безопасности** — просматривает и проверяет заявки, принимает решения по ним и изменяет состояние оформленных пропусков.
- **Администратор** — управляет учётными записями и ролями пользователей, контролирует журнал событий безопасности и административные настройки.

## 2. Правила разграничения доступа

Доступ к функциям системы предоставляется в соответствии с назначенной пользователю ролью.

Пользователь не должен получать права, которые не предусмотрены его ролью.

Действия, которые явно не разрешены матрицей доступа, считаются запрещёнными.

Неаутентифицированному пользователю доступ к прикладным данным, административным операциям и журналу событий безопасности не предоставляется.

| Операция | Заявитель | Сотрудник службы безопасности | Администратор |
|---|---|---|---|
| Создание заявки | Разрешено | Запрещено | Запрещено |
| Просмотр заявки | Только собственные | В рамках служебных полномочий | Только служебные сведения |
| Проверка заявки | Запрещено | Разрешено | Запрещено |
| Одобрение или отклонение заявки | Запрещено | Разрешено | Запрещено |
| Изменение состояния пропуска | Запрещено | Разрешено для обслуживаемых записей | Запрещено |
| Поиск и фильтрация заявок | Собственные | Доступные по полномочиям | По служебным задачам |
| Формирование отчётов | Запрещено | Разрешено | Разрешено |
| Управление учётными записями и ролями | Запрещено | Запрещено | Разрешено |
| Просмотр журнала безопасности | Запрещено | Запрещено | Разрешено |
| Изменение конфигурации | Запрещено | Запрещено | В пределах административных полномочий |

## 4. Ограничения доступа к данным

### Заявитель

Заявитель имеет доступ только к собственным заявкам и связанным с ними сведениям.

Заявитель не имеет доступа к:

- заявкам других пользователей;
- журналу событий безопасности;
- административным настройкам;
- управлению ролями;
- изменению состояния чужих пропусков.

### Сотрудник службы безопасности

Сотрудник службы безопасности имеет доступ к заявкам, необходимым для выполнения служебных обязанностей.

Он может:

- просматривать заявки;
- проверять предоставленные сведения;
- принимать решения по заявкам;
- изменять состояние оформленных пропусков;
- формировать предусмотренные отчёты.

Сотрудник службы безопасности не может:

- управлять ролями пользователей;
- изменять административные настройки;
- просматривать журнал событий безопасности, если это не предусмотрено отдельным полномочием.

### Администратор

Администратор имеет административные полномочия, необходимые для управления пользователями и настройками системы.

Администратор может:

- создавать и изменять учётные записи;
- назначать роли;
- контролировать состояние учётных записей;
- просматривать журнал событий безопасности;
- выполнять административные настройки.

Администратор не получает автоматически право изменять прикладные данные заявок и пропусков, если такое право не предусмотрено отдельным полномочием.

## 5. Принцип минимальных привилегий

Каждой роли предоставляется только тот набор полномочий, который необходим для выполнения соответствующих функций.

Заявитель получает минимальные права для подачи и контроля собственной заявки.

Сотрудник службы безопасности получает права, необходимые для обработки заявок и контроля пропусков.

Администратор получает административные права, необходимые для управления пользователями, ролями и настройками системы.

## 6. Запрет несанкционированных операций

При попытке пользователя выполнить операцию, запрещённую для его роли, система должна отклонить запрос.

При этом данные, к которым пользователь не имеет доступа, не должны возвращаться в ответе.

Запрещённая операция не должна приводить к изменению защищаемых данных.
