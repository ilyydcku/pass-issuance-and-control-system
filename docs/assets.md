# Реестр обрабатываемых данных и защищаемых активов

## 1. Обрабатываемые данные

| Категория данных | Пример полей | Источник | Хранение | Ограничение доступа |
|---|---|---|---|---|
| Данные пользователей | ID, ФИО, роль, статус учётной записи | Пользователь, администратор | База данных | По полномочиям |
| Заявки на оформление пропусков | ID заявки, заявитель, основание, тип пропуска, статус | Заявитель | База данных | Заявитель — собственные, сотрудник службы безопасности — служебные |
| Идентификационные сведения | Табельный номер, условный номер документа | Заявитель, сотрудник службы безопасности | База данных | По полномочиям |
| Сведения о пропусках | Номер, тип, дата выдачи, срок действия, статус | Сотрудник службы безопасности | База данных | Сотрудник службы безопасности, администратор |
| Решения по заявкам | Решение, исполнитель, комментарий, время | Сотрудник службы безопасности | База данных | По полномочиям |
| История изменений | Предыдущее значение, новое значение, исполнитель, время | Приложение | База данных | Уполномоченные пользователи |
| События безопасности | Исполнитель, действие, объект, время, результат | Приложение | Журнал событий | Администратор |
| Параметры конфигурации | Режим работы, имена параметров, секретные параметры | Администратор среды | Локальная конфигурация | Обслуживающие компоненты |
| Данные отчётов | Период, фильтры, статистические результаты | Приложение | По данным системы | По полномочиям |

## 2. Реестр защищаемых активов

Для оценки значимости активов используется шкала от 1 до 3:

- 1 — низкая значимость;
- 2 — средняя значимость;
- 3 — высокая значимость.

Ci — значимость конфиденциальности.

Ii — значимость целостности.

Ai — значимость доступности.

Ki = max(Ci, Ii, Ai).

| ID | Актив | Ответственный | Ci | Ii | Ai | Ki |
|---|---|---|---:|---:|---:|---:|
| AS-01 | Заявки на оформление пропусков | Владелец процесса оформления | 3 | 3 | 3 | 3 |
| AS-02 | Сведения об оформленных пропусках | Сотрудник службы безопасности | 3 | 3 | 3 | 3 |
| AS-03 | Учётные записи и роли пользователей | Администратор | 2 | 3 | 3 | 3 |
| AS-04 | Журнал событий безопасности | Администратор | 2 | 3 | 2 | 3 |
| AS-05 | Параметры конфигурации и секретные параметры | Администратор среды | 3 | 3 | 2 | 3 |
| AS-06 | Исходный код приложения | Разработчик | 1 | 3 | 2 | 3 |
| AS-07 | История изменений заявок и пропусков | Владелец процесса оформления | 3 | 3 | 2 | 3 |
| AS-08 | Работоспособность сервиса оформления пропусков | Владелец сервиса | 1 | 2 | 3 | 3 |

## 3. Обоснование оценок

### AS-01. Заявки на оформление пропусков

Конфиденциальность оценена в 3 балла, поскольку заявки могут содержать персональные и служебные сведения. Целостность оценена в 3 балла, поскольку подмена или изменение заявки может привести к неправомерному оформлению пропуска. Доступность оценена в 3 балла, поскольку недоступность заявок препятствует процессу оформления пропусков.

### AS-02. Сведения об оформленных пропусках

Конфиденциальность оценена в 3 балла, поскольку сведения о пропусках относятся к информации ограниченного доступа. Целостность оценена в 3 балла, поскольку изменение номера, статуса или срока действия пропуска может привести к нарушению контроля доступа. Доступность оценена в 3 балла, поскольку без этих данных невозможно оперативно контролировать выданные пропуска.

### AS-03. Учётные записи и роли пользователей

Конфиденциальность оценена в 2 балла. Целостность и доступность оценены в 3 балла, поскольку изменение роли пользователя может привести к предоставлению избыточных полномочий, а недоступность учётных записей нарушает работу пользователей системы.

### AS-04. Журнал событий безопасности

Конфиденциальность оценена в 2 балла, поскольку журнал может содержать сведения о действиях пользователей. Целостность оценена в 3 балла, поскольку изменение журнала искажает историю событий. Доступность оценена в 2 балла, так как кратковременная недоступность журнала не останавливает основную функцию оформления пропусков.

### AS-05. Параметры конфигурации и секретные параметры

Конфиденциальность и целостность оценены в 3 балла, поскольку раскрытие или изменение параметров может привести к нарушению защиты и неправильному режиму работы приложения. Доступность оценена в 2 балла, поскольку локальная конфигурация может быть восстановлена.

### AS-06. Исходный код приложения

Конфиденциальность оценена в 1 балл, поскольку учебный исходный код не должен содержать реальные секреты. Целостность оценена в 3 балла, поскольку изменение кода может привести к появлению уязвимого поведения. Доступность оценена в 2 балла.

### AS-07. История изменений заявок и пропусков

Конфиденциальность оценена в 3 балла, поскольку история может содержать сведения о действиях сотрудников и состояниях пропусков. Целостность оценена в 3 балла, поскольку подмена истории затрудняет восстановление фактической последовательности действий. Доступность оценена в 2 балла.

### AS-08. Работоспособность сервиса оформления пропусков

Конфиденциальность оценена в 1 балл, целостность — в 2 балла, доступность — в 3 балла. Недоступность системы делает невозможным выполнение основной функции оформления и контроля пропусков.
