# Система оформления и контроля пропусков

## Назначение

Учебная программная система для оформления и контроля пропусков.

## Индивидуальный вариант

Вариант 15: «Система оформления и контроля пропусков».

## Основные роли пользователей

- заявитель;
- сотрудник службы безопасности;
- администратор.

## Используемые технологии

- Python;
- Git;
- pytest;
- python-dotenv.

## Запуск проекта

1. Создать виртуальное окружение.
2. Установить зависимости.
3. Создать `.env` на основе `.env.example`.
4. Выполнить `python -m app.main`.

## Тестирование

Выполнить команду `pytest -v`.

## Требования безопасности

- секреты не хранятся в исходном коде;
- конфигурация проверяется при запуске;
- секретные значения не выводятся пользователю;
- зависимости проекта фиксируются.

## Версия v0.3

Подготовлены:

- описание области анализа и допущений;
- модель нарушителя;
- диаграмма потоков данных и границы доверия;
- перечень точек входа;
- 12 сценариев угроз с покрытием всех шести категорий STRIDE;
- реестр 12 рисков с обоснованием вероятности и последствий;
- подробный план обработки трех приоритетных рисков;
- уточненные требования безопасности SEC-13 - SEC-17 и приемочные сценарии AT-07 - AT-11;
- итоговая таблица прослеживаемости.

Модель угроз относится преимущественно к проектируемой системе. Предполагаемые недостатки не считаются обнаруженными уязвимостями, пока соответствующие компоненты не реализованы и не проверены.

Запланированные защитные меры не считаются действующими, а прогнозируемое снижение риска требует последующего подтверждения тестами.

## Версия v0.4

Спроектирована защищенная архитектура приложения:

- выбраны 5 значимых угроз из модели v0.3 и определены архитектурные ответы;
- выделены Interface, Validation, Authentication, Authorization, Services, Repository, Storage, Audit и Configuration;
- определены точки входа и 4 доверительные границы;
- сформированы архитектурная схема и матрица "угроза - защита";
- определены механизм аутентификации, модель ролей и разрешений, правила валидации, журналирования и хранения конфигурации;
- создана структура Python-проекта для защищенной архитектуры;
- реализованы прототипы validation.py, access_control.py и audit_logger.py;
- добавлен минимальный сервисный сценарий защищенной операции;
- добавлены тесты корректных и некорректных данных, недостаточных полномочий, журнала безопасности и Fail Secure.

Полная аутентификация, база данных и предметная реализация Repository остаются последующими этапами. Остаточные риски в архитектурной матрице являются прогнозными до полной реализации и проверки мер.
